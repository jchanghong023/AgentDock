# Windows 卡顿修复与对比

2026-09-07，同一 Windows 主机、1240 × 820 窗口、tiny-skia CPU 渲染。

## 原因和修复

- 上一版交互实例使用未优化的 Debug 二进制；本次交付 Release 优化构建。
  同时对开发构建的第三方依赖开启 opt-level=2，避免默认 cargo run 的字体/软件渲染仍不优化。
- 终端逐字符独立提交文本并创建裁剪层，满屏时产生数千个绘制操作。
  改为一个终端裁剪层、连续同样式 ASCII 文本合并绘制，跳过默认背景的重复填充。
  中文宽字符保持独立单元格，颜色、选区、下划线及粗斜体变化会断开文本批次。
- 原先有活动 Shell 时每 32ms 都发送 Tick，空闲也重新构建界面。
  现在由后台订阅每 16ms 检查队列，有数据才通知 UI；每秒保留一次退出状态和保存重试检查。
- 键盘释放、焦点/鼠标上报不再无条件复制整个终端快照；只在可见状态 generation 改变时复制。

## 实测

`terminal-load.ps1` 在真实 ConPTY 中生成 240 帧、每帧 30 行彩色 ASCII 文本，
帧间等待 33ms。启动预热 2 秒后采样 10 秒进程 CPU 时间。两个版本依次运行。
均目视确认完整显示最终帧 0239 与 DEVHUB_RENDER_LOAD_DONE 标记。

| 测量 | 旧 Debug | 修复后 Release |
| --- | ---: | ---: |
| 满屏刷新，10 秒 CPU 时间 | 9937.5 ms | 3046.875 ms |
| 工作集 | 61.77 MiB | 52.84 MiB |
| 输出停止后，5 秒 CPU 时间 | 546.875 ms | 62.5 ms |

该负载 CPU 时间下降约 69.3%，空闲采样下降约 88.6%。数值是 CPU 核心时间，
不是整机任务管理器百分比、帧率或输入延迟；同时包含代码优化和构建优化的收益。
空闲采样时旧窗口在后台、新窗口在前台。未将这些结果推广为所有 TUI 的性能保证。

原始数据：perf-before.json、perf-after.json、perf-idle.json。
本次新增文本分批边界及空闲/数据唤醒回归测试，保留真实 PTY 和 ANSI/中文测试。
