# Windows 性能修复实测（2026-09-08）

本次已解决历史批量导入的重复扫描/排序、选区变化的整屏快照失效、滚动时绘制缓存随屏幕位置失效，以及输入队列满后上游写线程退出的问题。相同尺寸的 PTY resize 也已去重。

## 环境与方法

- Windows 11 专业版 10.0.26200 x64，AMD Ryzen 9 9950X，16 核 / 32 线程。
- Rust/Cargo 1.98.0，MSVC；同机、同锁定依赖、同 Release 配置比较，未使用 Debug 基线。
- 基线为本次修改前源码编译的二进制，增加了同一份基准负载；保存在 `.tmp/agentdock-before.exe` 和 `.tmp/terminal-perf-before.exe`。
- 最终程序：`.tmp/target/release/agentdock.exe`。所有构建、依赖缓存、测试状态和采样文件均位于 Git 忽略的 `.tmp/`。
- 微基准使用 `examples/terminal_perf.rs`，每个版本独立运行三次，表中为中位数。终端视口 140 列 × 40 行，包含中文与 ANSI 颜色。

## 可重复的局部性能收益

| 操作 | 修改前（ms） | 最终版本（ms） |
| --- | ---: | ---: |
| 首次导入 1,000 条历史 | 20.65 | 0.37 |
| 原样重复导入 1,000 条历史 | 19.61 | 0.20 |
| 首次导入 10,000 条历史 | 2060.91 | 3.71 |
| 原样重复导入 10,000 条历史 | 2118.27 | 2.08 |
| 1000 次单行选区变化：快照累计 | 174.64 | 5.50 |
| 1000 次光标变化：快照累计 | 1.15 | 1.15 |
| 1000 次单行文字更新：快照累计 | 5.01 | 5.08 |
| 1000 次全屏更新：快照累计 | 238.78 | 237.12 |

一万条历史首次导入耗时降低约 99.8%；选区快照耗时降低约 96.9%。这些是指定代码路径的测量，不是 GUI 帧率或输入回显延迟。

一万条首次导入三次原始值：修改前 2043.70 / 2104.89 / 2060.91 ms；最终 3.75 / 3.71 / 3.63 ms。
选区快照三次原始值：修改前 180.16 / 172.62 / 174.64 ms；最终 5.51 / 5.40 / 5.50 ms。

历史导入使用批次内的项目路径和会话文件索引，更新完后每个受影响项目只排序一次，保留原会话 ID、启动参数和历史记录。它仍接收完整记录集合，不是后台增量同步。
选区缓存按稳定行号比较新旧选中列范围；未受影响的行保留 Arc 内容身份。绘制缓存随内容身份复用，滚动后不再因为屏幕行号变化而重建同一行的绘制片段。

## 实际 GUI 与 ConPTY

通过真实 Windows GUI/ConPTY 执行固定 PowerShell 回放：300 帧、每帧 30 行中文/英文/框线混合文本，帧间等待 25 ms。窗口配置 1240×820，默认字体 Consolas 15，同一桌面环境；隔离 OMP 扫描目录与应用状态。启动后等待 3 秒，再采样约 8 秒进程 CPU 时间。

| GUI CPU 核心时间（ms） | 第 1 次 | 第 2 次 | 第 3 次 |
| --- | ---: | ---: | ---: |
| 修改前 | 2015.625 | 2468.750 | 1843.750 |
| 最终版本 | 1859.375 | 2015.625 | 1640.625 |

最终版本工作集约 46 MiB。所有采样均检测到非零窗口句柄，进程未异常退出，stderr 为空。额外 GUI 冒烟检查正常退出，并输出 `AGENTDOCK_GUI_SMOKE_EVENT_LOOP_OK`。

GUI 采样存在明显波动：这是固定时间窗口的 CPU 核心时间，包含启动/输出节奏影响，没有逐帧同步、像素核验或拆分绘制与窗口提交。因此不能由这些数字确认中文整体绘制提速、稳定帧率或无卡顿。没有把局部微基准收益推广为完整 GUI 收益。

`cargo test --release --locked --offline`：**57 项通过，0 失败**。覆盖真实 ConPTY 往返与尺寸调整、Unicode/ANSI、选区缓存与无缓存结果一致、滚动绘制片段复用、历史重复记录更新和 ID 保留。

输入背压另有两层回归：适配器通道压满后恢复读取，逐字节核对顺序；真实 WezTerm 写线程连接有界适配器后暂停消费，再完整收到 100 次中文输入，随后仍能发送新输入。这里的受控阻塞发生在适配器接收端；没有宣称已在真实子进程停止读取的场景测出输入尾延迟。等待容量发生在 WezTerm 专用写线程，UI 不等待该队列。上游无界队列的总内存限制仍未解决。

## 兼容性与尚未验证的范围

Cargo.toml、Cargo.lock、软件渲染/X11 选项及 `vendor/winit` 无 XKEYBOARD 补丁均未改变。没有加入 GPU 要求、平台专用依赖或 `target-cpu=native`。

**内部 CentOS 7 / 旧 X11 机器没有在本次连接、编译或运行，不能据 Windows 实测声明旧系统兼容验收完成。** 原有兼容目标与补丁得到保留；实际 ABI、旧内核、字体和远程窗口提交仍须在目标环境验证。

终端内核仍在 UI 线程；中文/框线仍按原来的网格定位绘制。本次未实施后台内核迁移、中文段排版合并、启动路径重构或窗口脏区域提交。未测 1/4/16 活跃标签的输入 P50/P95/P99、最长 UI 停顿及实际 OMP 网络负载，因此不声明所有持续输出卡顿已经解决。
